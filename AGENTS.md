## Project rules
- All site content lives in Supabase tables; `src/lib/seed.ts` is the single source for starter rows and the built-in fallback when Supabase env vars are missing. Why: site works before the DB exists and the SQL never drifts.
- `supabase/setup.sql` is generated by `bun scripts/gen-sql.ts`; edit the generator/seed, not the SQL. Why: one source of truth.
- Submissions are inserted only by the `submitRequest` server function with the service key, saved before notifications. Why: no public writes to private tables, notifications can't lose data.
- Admin access is enforced by the `is_admin()` RLS function backed by `admin_emails`. Why: security must not rely on UI.
